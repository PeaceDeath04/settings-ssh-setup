# SSH Hardening Setup

Bash-скрипт для базового усиления безопасности SSH на Ubuntu VPS.

Скрипт автоматически создаёт отдельного SSH-пользователя, настраивает вход только по SSH-ключу, отключает вход `root`, меняет SSH-порт, настраивает `ssh.socket` через systemd и обновляет правила UFW.

> ⚠️ **Важно:** не закрывайте текущую SSH-сессию, пока не проверите новое подключение к серверу через новый порт и нового пользователя.

---

## Возможности

Скрипт выполняет следующие действия:

* создаёт SSH-пользователя или использует существующего;
* добавляет пользователя в группу `sudo`;
* устанавливает указанный публичный SSH-ключ;
* отключает вход `root` через SSH;
* отключает авторизацию по паролю;
* отключает `keyboard-interactive` авторизацию;
* разрешает авторизацию по публичному ключу;
* ограничивает SSH-доступ через `AllowUsers`;
* позволяет выбрать SSH-порт или автоматически генерирует случайный порт;
* поддерживает диапазон портов `20000–60000`;
* проверяет, свободен ли выбранный порт;
* проверяет итоговую конфигурацию через `sshd -t` и `sshd -T`;
* настраивает `systemd ssh.socket`, если он используется;
* добавляет новый SSH-порт в UFW;
* удаляет правило `22/tcp` из UFW;
* проверяет, что порт `22` больше не слушается;
* проверяет, что новый SSH-порт действительно слушается;
* проверяет права на `.ssh` и `authorized_keys`.

---

## Требования

Скрипт рассчитан прежде всего на Ubuntu Server.

Необходимы:

* `bash`
* `sudo`
* `openssh-server`
* `systemd`
* `ufw` — опционально

Запускать скрипт необходимо от пользователя, имеющего права `sudo`.

## Установка

Скачать скрипт:

```bash
git clone https://github.com/PeaceDeath04/settings-ssh-setup.git
cd settings-ssh-setup
```

Сделать файл исполняемым:

```bash
chmod +x setup-ssh-settings.sh
```

Запустить:

```bash
sudo ./setup-ssh-settings.sh
```

---

## Что потребуется ввести

При запуске скрипт запросит три параметра.

### SSH-пользователь

```text
Имя главного SSH-пользователя:
```

Например:

```text
admin
```

Пользователь получит права `sudo`.

---

### SSH-порт

```text
SSH-порт [Enter = случайный 20000-60000]:
```

Можно указать собственный порт:

```text
49268
```

или просто нажать `Enter`.

В таком случае скрипт случайным образом выберет порт из диапазона:

```text
20000–60000
```

---

### Публичный SSH-ключ

```text
Ваш публичный SSH-ключ:
```

Например:

```text
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... user@computer
```

Использовать необходимо именно **публичный** ключ.

Приватный ключ (`.ppk`, `id_ed25519`, `id_rsa` и т. п.) вводить в скрипт **нельзя**.

---

## Что происходит с SSH

Скрипт создаёт конфигурацию:

```text
/etc/ssh/sshd_config.d/01-my-settings-ssh.conf
```

В ней задаются основные параметры:

```text
Port <выбранный порт>

PermitRootLogin no

PasswordAuthentication no

KbdInteractiveAuthentication no

PubkeyAuthentication yes

AllowUsers <выбранный пользователь>
```

Таким образом:

* `root` больше не может войти через SSH;
* парольная авторизация отключена;
* разрешён вход по SSH-ключу;
* подключаться через SSH может только указанный пользователь;
* SSH работает через выбранный порт.

---

## Почему используется `01-my-settings-ssh.conf`

Ubuntu может загружать дополнительные SSH-конфигурации из:

```text
/etc/ssh/sshd_config.d/
```

Файлы читаются в лексикографическом порядке.

Поэтому конфигурация скрипта называется:

```text
01-my-settings-ssh.conf
```

Это позволяет задать основные параметры до файлов вроде:

```text
50-cloud-init.conf
```

---

## systemd `ssh.socket`

На некоторых системах SSH может использовать systemd socket activation.

В таком случае одного изменения:

```text
/etc/ssh/sshd_config
```

может быть недостаточно.

`ssh.socket` может продолжать слушать старый порт `22`.

Поэтому скрипт при обнаружении `ssh.socket` создаёт:

```text
/etc/systemd/system/ssh.socket.d/override.conf
```

с выбранным SSH-портом.

После этого выполняется:

```bash
systemctl daemon-reload
systemctl restart ssh.socket
systemctl restart ssh
```

## UFW

Если UFW активен, скрипт:

1. разрешает новый SSH-порт;
2. проверяет наличие правила `22/tcp`;
3. удаляет `22/tcp`;
4. проверяет, что новый порт разрешён;
5. проверяет, что `22/tcp` больше не разрешён.

Например:

```text
49268/tcp ALLOW
```

вместо:

```text
22/tcp ALLOW
```

Если UFW не активен, правила UFW не изменяются.

## Проверки

Перед завершением скрипт проверяет:

### SSH-конфигурацию

```bash
sshd -t
```

### Эффективные параметры SSH

```bash
sshd -T
```

Проверяются:

* SSH-порт;
* `PermitRootLogin`;
* `PasswordAuthentication`;
* `KbdInteractiveAuthentication`;
* `PubkeyAuthentication`;
* `AllowUsers`.

### Реальный listening port

Проверяется через:

```bash
ss -lntp
```

Это важно, потому что конфигурация может содержать новый порт, а другой компонент системы всё ещё может слушать `22`.

### SSH-пользователя

Проверяется наличие пользователя и членство в группе:

```text
sudo
```

### SSH-ключ

Проверяются:

```text
~/.ssh
```

с правами:

```text
700
```

и:

```text
authorized_keys
```

с правами:

```text
600
```

## После установки

После успешного завершения скрипт покажет команду для нового подключения:

```bash
ssh -p <SSH_PORT> <SSH_USER>@IP_СЕРВЕРА
```

Например:

```bash
ssh -p 49268 admin@203.0.113.10
```

Сначала необходимо открыть **новое SSH-подключение** и убедиться, что всё работает.

Только после успешного подключения рекомендуется закрывать старую SSH-сессию.

---

## Важное предупреждение

Этот скрипт изменяет критические параметры SSH.

Ошибка в SSH-конфигурации или потеря приватного ключа может привести к потере доступа к серверу.

Перед запуском убедитесь, что:

* у вас есть рабочий приватный SSH-ключ;
* публичный ключ соответствует приватному;
* вы имеете доступ к консоли VPS или другому аварийному доступу;
* текущую SSH-сессию можно оставить открытой до завершения проверки.

**Не закрывайте текущую SSH-сессию сразу после запуска.**

---

## Безопасность

Скрипт не содержит:

* приватных SSH-ключей;
* паролей;
* API-токенов;
* Cloudflare API keys;
* секретов VPS;
* credentials.

Публичный SSH-ключ не является секретом и может использоваться в `authorized_keys`.

Не добавляйте в репозиторий:

```text
*.ppk
*.pem
id_rsa
id_ed25519
.env
.env.*
credentials.*
secrets.*
```

Рекомендуется использовать `.gitignore`.

---

## Ограничения

Скрипт предназначен для базового SSH hardening и не является полноценным security-аудитом сервера.

Он не настраивает:

* fail2ban;
* VPN;
* firewall policy для приложений;
* автоматические обновления;
* аудит системы;
* SELinux/AppArmor;
* мониторинг;
* резервное копирование.

Конкретная конфигурация VPS, Docker, cloud-init и systemd может отличаться, поэтому после выполнения скрипта необходимо проверить подключение вручную.
